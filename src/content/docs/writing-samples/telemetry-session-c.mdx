Coordinates are normalized (0.0 to 1.0). `CONTENT_TYPE` hints what the encoder should preserve details in:
- `TEXT` like subtitles, UI labels, and the like need sharp edges.
- `FACE` (character portraits) needs smooth gradients.
- `DEFAULT` is all other content.

If you ask for more regions than `max_rois`, the SDK only honors the first `max_rois`.

When you change scenes, call `ngp_encoder_notify_scene_change(sdk);` to tell the encoder to start fresh. Without this hint, the first frame of a new scene could look blocky.

## Best practices for telemetry and backend APIs

- **Log telemetry events at meaningful moments, not on every frame.**
- **Always include the session ID in bug reports and support flows.** It's the bridge from "this happened to me" to "I can find your logs in our system."
- **Use context variables for tunables — but ship sensible defaults.** Don't make the default branch crash. Treat context as "the server can override these," not "the server must provide these."
- **Send encoder hints every frame, even if they're the same.** It's a set-style API, not a change-style one — the encoder needs the current state per-frame.
- **Call `notify_scene_change` on cuts**, especially loading screens. The visual quality difference is real.
- **For custom telemetry, use a schema.** Decide once what shape your `json_payload` takes per event name, and stick to it.
- **Treat telemetry as fire-and-forget.** Don't try to wait for it to send before progressing the game. The SDK takes care of retries.
