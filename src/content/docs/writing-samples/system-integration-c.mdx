## Deeplinks APIs

A deeplink is a URL that can launch your game with a payload you choose. You can use deeplinks to streamline a player's journey to specific content, bypassing navigation through introductory menus and selections. These links can be integrated in various locations, such as social media posts, push notifications, within Company's Game Discovery section, and more. 

Any players that don't already have the game installed will be routed to their respective app store (**Google Play Store** or **Apple App Store**) to download it.

## Best practices for integrating with the Company service

- **Wire both `modal-active` and `display-inactive` to the same `pause()` function.** This reduces a common bug of pausing only on modal events and missing the case where the OS minimizes your game.
- **Check current state on startup, don't rely only on callbacks.** Both modal and display state could already be in their "inactive" state when your game launches. Call `is_active()` once at boot to sync up.
- **Treat deeplink payloads as untrusted input.** They came from outside your game. Validate every field, bound every length, don't deserialize directly into game state.
- **For QR codes, copy bytes immediately.** Don't hold the pointer past the callback. Don't rely on it surviving the next `run_callbacks`.
- **Use `available_input` for hints, not for behavior.** Some players may have a keyboard plugged in but prefer the controller. Adapt hints, but let players still use whatever they want.
- **Don't poll latency every frame.** It changes slowly. Once a second is plenty for UI tuning.
