You use the Controller APIs to connect/disconnect, query controller status, and listen for input specifics. For Company, a controller can be the **Company Game Controller**, a keyboard, a mouse, or some combination. When your players pick up a controller, the SDK calls your "add controller" callback. When they put it down, you get your "controller removed" callback. In between, you bind callbacks for the input types you care about and the C SDK pushes input events to you.

## Best practices for the controller

- **Bind your callbacks in `controller_added`, not at startup.**
- **Drop the pointer when you get `controller_removed`.** Using it after that is undefined behavior. Keep your controller map keyed by `ngp_controller*` and erase the entry on remove.
- **Use `input_connected` to learn axis ranges.** Don't hardcode any axis ranges. Read it from the device's definitions.
- **Always handle the keyboard and mouse.** Company runs on a lot of devices. A player might pair a Bluetooth keyboard at any time.
- **Use the SDK's input source (`NGP_SDK_INPUT_SOURCE_SDK`) when targeting cloud/secondary players.** Without it, you'll only get the primary user's input from the operating system.
