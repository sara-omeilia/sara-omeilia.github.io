:::caution[Limited release]
The C SDK is a limited release SDK for Company. It does not follow a standard release schedule, and it is only available to specific partners.

Speak with your Company Producer for more information and access.
:::

The C SDK supports Company Cloud games through an engine-agnostic C API. It is a series of shared libraries (one for each platform) and a set of header files. The headers are platform-agnostic.

## Download the C SDK

To download the C SDK,

<Steps>

1. Log into **Games Workspace**.
2. Select your game.
3. From **SDK & Credentials**, select the **Download SDK and Credentials** dropdown and select **C**.
4. Select **Download** for the latest C SDK.

</Steps>

Once downloaded, you can see the shared header files within the `include/` folder in the C SDK:
<FileTree>

- Company_games_sdk_c-XXXX.X.X/
    - **include/** the headers (shared by all platforms)
        - Company_games_sdk_export.h
        - Company/
            - games/
                - sdk.h the main one
                - account.h
                - player.h
                - config.h
                - error.h
                - types.h
                - cppapi.h C++ helpers; ignore in pure C
                - api_macros.h
                - api/ feature headers: achievements, leaderboards, etc.
                    - achievements.h
                    - leaderboards.h
                    - ...

</FileTree>

There are two library files per platform that your game needs at runtime: `libCompany_games_sdk` and `libngp_ssic.1`.
<FileTree>

- Company_games_sdk_C-XXXX.X.X/
    - **darwin/** macOS binaries
        - arm64/lib/ Apple Silicon (M1/M2/M3 Macs)
            - libCompany_games_sdk.dylib
            - libngp_ssic.1.dylib
        - x86_64/lib/ Intel Macs
            - libCompany_games_sdk.dylib
            - libngp_ssic.1.dylib
    - **linux/x86_84/lib/** Desktop Linux (Intel/AMD 64-bit)
        - libCompany_games_sdk.so
        - libngp_ssic.1.so
    - **cloud/x86_64/lib/** Company Cloud Gaming (separate build)
        - libCompany_games_sdk.so
        - libngp_ssic.1.so
    - **windows/x86_64/** Windows 64-bit
        - bin/ runtime DLLs (these go next to your .exe)
            - Company_games_sdk.dll
            - libngp_ssic.1.dll
            - libgcc_s_seh-1.dll compiler runtime
            - libstdc++-6.dll compiler runtime
            - libwinpthread-1.dll compiler runtime
        - lib/
            - Company_games_sdk.lib import library (linker uses this)

</FileTree>

:::note[Linux versus Cloud libraries]
The Cloud and Linux SDK binaries are different and mutally-exclusive.

The Linux SDK binary operates similarly to the Windows and Mac SDK binaries, and they support the **Controller Editor** from a desktop. 

The Cloud SDK binary only works while on OCGA and does not support the **Controller Editor**.
:::

## C integration

After downloading the C SDK from **Games Workspace**, you must integrate it with your game. For C++ engines, see the [C++ integration](#c-integration-1) guidance and example.

<Steps>

1. Copy both library files (`libCompany_games_sdk` and `libngp_ssic.1`) for your platform next to your game executable.
    - Mac users need to be sure you are using the correct library files for your OS.
        - Apple Silicon (M1/M2/M3 Macs) should use the libraries from `darwin/arm64/lib/`.
        - Intel Macs should use the libraries from `darwin/x86_64/lib/`.
    - Windows users must copy all the DLLs from `windows/x86_64/bin/` as well as the library files next to your .exe.
2. Copy the `/Company` folder with all its contents next to your .exe.
3. Configure the SDK. The `project_root` should be an absolute path.

    ```c
    #include "Company/games/sdk.h"
    #include "Company/games/config.h"

    static ngp_sdk* g_sdk = NULL;
    static int g_sdk_ready = 0;

    static void on_sdk_created(ngp_result result, ngp_sdk* sdk, void* user_data) {
        (void)user_data;
        if (!result.ok) {
            fprintf(stderr, "SDK init failed: %s\n", result.error);
            return;
        }
        // WARNING: this runs on a different thread from your main loop.
        g_sdk = sdk;
        g_sdk_ready = 1;
    }

    void init_Company_sdk(const char* project_root) {
        ngp_set_sdk_logging_level(NGP_LOG_LEVEL_INFO);
        ngp_config* config = ngp_config_create();
        ngp_config_set_user_project_root(config, project_root);
        ngp_sdk_create(config, on_sdk_created, NULL);
    }
    ```

4. Include `ngp_sdk_run_callbacks` in your event loop to receive all state changes and callbacks on the main thread. (Sara note: Link to relevant event loop and threading section/s on the framework page.)

    ```c
    while (sdk == NULL) sleep(10);

    // Once we have the sdk, we can make calls available to the ngp_sdk context object, 
    // which includes all controller/display APIs.
    ngp_display* display = ngp_sdk_get_primary_display(sdk);

    bool is_active = false;
    ngp_display_add_is_active_changed_callback(
    display, handle_display_is_active, (void*)&is_active
    );

    while(!is_active) {
        // Important: This needs to be called periodically for the SDK to advance state and 
        // call async/event callbacks! Typically in your game loop or on a short timer rather 
        // than like this example.
        ngp_sdk_run_callbacks(sdk);
    sleep(10); // Sleep is just for the example.
    }
    ```

5. Log in to access the account object. This is required to access your players.

    ```c
    ngp_account* account = NULL;
    ngp_sdk_log_in(
        sdk,
        &handle_log_in,
        (void*)&account
    );

    while(account == NULL) {
        ngp_sdk_run_callbacks(sdk);
    sleep(10); // Sleep is just for the example.
    }
    ```

6. Call the player object to use the different APIs *(Sara note: Link to APIs section on the framework page)*.

    ```c
    ngp_player* player = NULL;
    while(player == NULL) {
        // There are also current_player_changed events in account.h. You should use both.
        player = ngp_account_get_current_player(account);
    sleep(10); // Sleep is just for the example.
    }

    ngp_blobs_read(player, "blah", some_callback, some_user_data);
    ngp_stats_submit(player, "name", 52, some_other_callback, some_user_data);
    // And so on...!
    ```

7. Destroy the SDK when done.

    ```c
    int main(void) {
        ...
    // You need to use this function for proper destruction.
        ngp_sdk_destroy(sdk);
        return 0;
    }
    ```

</Steps>

### C integration example

This example integrates the C SDK in a basic C application with inline comments explaining each step.

```c
#include "Company/games/sdk.h"
#include "Company/games/config.h"
#include "Company/games/api/display.h"

// This is an example of how to handle an async function.
void handle_sdk_created(ngp_result result, ngp_sdk* sdk, void* user_data) {
	// Always check results!
	if (result.ok) {
	// Since we stored our local sdk ptr as user_data, we can pull it out here.
*((ngp_sdk**)user_data) = sdk;
} else {
	// Failures have error codes.
	printf("error creating Company sdk: %s", result.error);
}
}

// This is an example of how to handle an sdk event.
void handle_display_is_active(ngp_display_is_active_changed* data, void* user_data) {
	// Since we stored our local sdk ptr as user_data, we can pull it out here.
*((bool**)is_active) = data->is_active;
// Note: You do not need to free the data ptr yourself, but also beware that after
// this callback it will be freed! Be careful with e.g. const char*!
}

void handle_log_in(ngp_result result, ngp_account* account, void* user_data) {
    assert(result.ok); // Maybe handle log in errors better, for your players' sakes...
    *((ngp_account**)user_data) = account;
}

int main(void) {
	// Note that you can bind the SDK logs into your own logger, and modify the
	// verbosity level:
	// ngp_add_log_received_callback(...)
	// ngp_set_sdk_logging_level(...)

	// This is how to configure the SDK. There's not much here right now.
ngp_config* config = ngp_config_create();

// This step is required for working with the Controller Editor.
ngp_config_set_user_project_root(config, "path/to/project/root");

ngp_sdk* sdk = NULL;

// Here we pass in the sdk ptr as "user_data". You can read more about this
// pattern below.
//
// Also note ownership of the config ptr is taken here, so you do not need
// to free it yourself.
ngp_sdk_create(config, &handle_sdk_created, (void*)&sdk);
// One final note... this is the one place an sdk callback _may_ be called
// from another thread. We don't handle that here, but you probably should.

// TODO: You'll probably want to wait for this without blocking your entire app. 
// For this example though, that's exactly what we'll do.
while (sdk == NULL) sleep(10);

// Once we have the sdk, we can make calls available to the ngp_sdk
// context object, which includes all controller/display APIs.
ngp_display* display = ngp_sdk_get_primary_display(sdk);

bool is_active = false;
ngp_display_add_is_active_changed_callback(
display, handle_display_is_active, (void*)&is_active
);

while(!is_active) {
	// Very important! This needs to be called periodically in order for the
	// SDK to advance state and call async/event callbacks! Probably in your
// game loop or on a short timer rather than like this.
	ngp_sdk_run_callbacks(sdk);
sleep(10); // Sleep is just for the example. :)
}

// Log-in to gain access to the account object.
ngp_account* account = NULL;
ngp_sdk_log_in(
	sdk,
	&handle_log_in,
	(void*)&account
);

while(account == NULL) {
	ngp_sdk_run_callbacks(sdk);
sleep(10); // Sleep is just for the example. :)
}

// Finally, we need the player object to make most of the fun API calls.
ngp_player* player = NULL;
while(player == NULL) {
	// Note there's also current_player_changed events in account.h
	// You probably want to use both.
	player = ngp_account_get_current_player(account);
sleep(10); // Sleep is just for the example. :)
}

ngp_blobs_read(player, "blah", some_callback, some_user_data);
ngp_stats_submit(player, "name", 52, some_other_callback, some_user_data);
// And so on...!

// Be sure to destroy the sdk when you're done with it! Yes, you need to use this
// function for proper destruction.
ngp_sdk_destroy(sdk);
return 0;
}
```

## C++ integration

After downloading the C SDK from **Games Workspace**, you must integrate it with your game. For C++ engines, the C SDK includes a few header-only, std-only, C++11-compliant helpers to ease common tasks. These operate on top of the C API, but do not modify it in any way.

The C++ helper adds macros and classes that simplify binding async and event callbacks for object methods.

<Steps>

1. Copy the library files for your platform next to your game executable.
    - Mac users need to be sure you are using the correct library files for your OS.
        - Apple Silicon (M1/M2/M3 Macs) should use the libraries from `darwin/arm64/lib/`.
        - Intel Macs should use the libraries from `darwin/x86_64/lib/`.
    - Windows users must copy all the DLLs from `windows/x86_64/bin/` as well as the library files next to your .exe.
2. Copy the `/Company` folder with all its contents next to your .exe. This is where the `cppapi.h` file exists.
3. Configure the SDK. The `project_root` should be an absolute path.

    ```c++
    #include "Company/games/sdk.h"
    #include "Company/games/config.h"
    #include "Company/games/cppapi.h"     // C++ ergonomics

    void init_Company_sdk(const std::string& project_root) {
        ngp_set_sdk_logging_level(NGP_LOG_LEVEL_INFO);

        ngp_config* config = ngp_config_create();
        ngp_config_set_user_project_root(config, project_root.c_str());

        // Lambda callback. No user_data plumbing — the macro handles it.
        ngp_sdk_create(config, NGP_ASYNC_CALLBACK(
            [](ngp_result result, ngp_sdk* sdk) {
                if (!result.ok) {
                    std::fprintf(stderr, "SDK init failed: %s\n", result.error);
                    return;
                }
                // Publish the pointer atomically — readers on the game thread will see it.
                g_sdk.store(sdk, std::memory_order_release);
            }
        ));
    }
    ```

4. Include `ngp_sdk_run_callbacks` in your event loop to receive all state changes and callbacks on the main thread. *(Sara note: Link to relevant event loop and threading section/s on the framework page.)*

    ```c++
    while (game_is_running) {
        poll_input();
        update_game(dt);

        if (ngp_sdk* sdk = g_sdk.load(std::memory_order_acquire); sdk) {
            ngp_result r = ngp_sdk_run_callbacks(sdk);
            if (!r.ok) std::fprintf(stderr, "run_callbacks error: %s\n", r.error);
        }

        render_frame();
    }
    ```

5. Log in to access the account object. This is required to next access your players.

    ```c++
    #include "Company/games/account.h"
    #include "Company/games/player.h"

    class GameSession {
    public:
        void start_login() {
            ngp_sdk* sdk = g_sdk.load(std::memory_order_acquire);
            if (!sdk) return;

            ngp_sdk_log_in(sdk, NGP_ASYNC_CALLBACK(
                [this](ngp_result result, ngp_account* account) {
                    if (!result.ok) {
                        std::fprintf(stderr, "Login failed: %s\n", result.error);
                        return;
                    }
                    handle_logged_in(account);
                }
            ));
        }

    private:
        void handle_logged_in(ngp_account* account) {
            _account = account;

            // Subscribe to player-changed FIRST. EventListener owns the subscription.
            _player_listener.bind(account,
                [this](ngp_player* player) {
                    _player = player;
                    if (player) {
                        const char* handle = ngp_player_get_handle(player);
                        std::printf("Active player: id=%s, handle=%s\n",
                                    ngp_player_get_id(player),
                                    handle ? handle : "(none)");
                    }
                }
            );

            // Then check if a player is already available.
            if (ngp_player* p = ngp_account_get_current_player(account)) {
                _player = p;
            }
        }

        ngp_account* _account = nullptr;
        ngp_player* _player = nullptr;

        // RAII: when this listener is destroyed, it unsubscribes automatically.
        // The NGP_EVENT_FNS macro expands to (&ngp_account_add_current_player_changed_callback,
        //                                      &ngp_account_remove_current_player_changed_callback).
        Company::games::EventListener<ngp_player, ngp_account> _player_listener{
            NGP_EVENT_FNS(account, current_player_changed)
        };
    };
    ```

6. Call the player object to use the different APIs *(Sara note: Link to APIs section on the framework page).* 

    ```c++
    #include "Company/games/api/achievements.h"

    void GameSession::unlock_first_boss() {
        if (!_player) return;

        ngp_achievements_unlock(_player, "first_boss_defeated",
            NGP_ASYNC_CALLBACK(
                [](ngp_result result, ngp_achievements_unlock_response* resp) {
                    if (!result.ok) {
                        std::fprintf(stderr, "Unlock failed: %s\n", result.error);
                        return;
                    }
                    std::printf("Unlocked: %s\n", resp->achievement.name);
                }
            )
        );
    }
    ```

7. Destroy the SDK when done. 

    ```c++
    int main(int argc, char** argv) {
        const char* project_root = (argc > 1) ? argv[1] : ".";

        init_Company_sdk(project_root);

        // ... game loop runs ...

        // Wrap the raw pointer in unique_ptr at the end so RAII handles cleanup.
        // (Or do this immediately after init — but you need synchronization since
        //  the create callback fires on another thread.)
        NgpSdkPtr owned{g_sdk.exchange(nullptr)};
        // owned's destructor calls ngp_sdk_destroy.
        return 0;
    }
    ```

</Steps>

### C++ integration example

This example shows macros and classes that simplify binding async and event callbacks for object methods.

```c++
#include "Company/games/sdk.h"
#include "Company/games/config.h"
#include "Company/games/cppapi.h" // C++ helpers live in here

class CompanySdk {
public:
    CompanySdk()
        // Initialize listeners by specifying the context object (display) add/remove
        // callback functions they use by event name (is_active_changed). This maps to:
        // ngp_display_{add,remove}_is_active_changed_callback.
        : _display_is_active_changed{NGP_EVENT_FNS(display, is_active_changed)} {

        // Same C call, but the macro replaces the user_data and callback params to
        // create a binding to a class method
        // instead of a free function.
        ngp_sdk_create(nullptr,
            NGP_ASYNC_CALLBACK(this, &CompanySdk::handle_sdk_initialized)
        );
    }

private:
    // Async callback functions has the same signature as the C callback would,
    // minus user_data.
    void handle_sdk_initialized(ngp_result result, ngp_sdk* sdk) {
        if (!result.ok) {
            std::cout << "error creating sdk: " << result.error;
            return;
        }
        _native_ptr = sdk;

        // Once you have access to the context object, you can bind your event.
        ngp_display* display = ngp_sdk_get_primary_display(sdk);
        _display_is_active_changed.bind(display,
            this, &CompanySdk::handle_display_is_active_changed
        );

        // You'll want to access ngp_account and ngp_player similar to the C API example.
        ngp_sdk_log_in(
            _native_ptr, NGP_ASYNC_CALLBACK(this,
                [](ngp_result result, ngp_account* account) {
                    // Yes you can use lambdas.
                }
            )
        );
    }

    // Event callbacks also have the same signature as the C callback, minus user_data.
    void handle_display_is_active_changed(ngp_display_is_active_changed* event) {
        // event->display
        // event->is_active
    }

    ngp_sdk* _native_ptr{nullptr};

    // Event listeners in C++ exist as member fields.
    // It takes the payload type (ngp_display_is_active_changed) and context object
    // (ngp_display) as generic params.
    //
    // These follow the RAII pattern for event registration, when this is destructed,
    // it will call the remove handler automatically.
    EventListener<ngp_display_is_active_changed, ngp_display> _display_is_active_changed;
};
```

## Connect to the Controller Editor

The **Controller Editor** enables you to design the **Company Game Controller** layout, connection mode, and configurations. This information exists in a `controller.yaml` file that must ship inside your game's `Company/` folder.

To connect the **Controller Editor** to your Windows, Mac, or Linux platform,

<Steps>

1. Set your `project_root` in the SDK configuration.

    ```c
    ngp_config* config = ngp_config_create();
    ngp_config_set_user_project_root(config, "path/to/project/root");
    ngp_sdk* sdk = NULL;
    ngp_sdk_create(config, &handle_sdk_created, (void*)&sdk);
    ```

2. Open the [**Controller Editor**](/game-controller/what-is-the-ngc/#the-controller-editor).
3. The configuration you set in the first step creates the `Company/` folder that stores your controller configuration .yaml file.
4. After creating or editing your controller in the **Controller Editor**, the `controller.yaml` (is updated at save.)/(requires you to replace the existing `controller.yaml` file with your most recent export.) < Unsure if either are correct

</Steps>

If you designed a layout in the **Controller Editor** before connecting to your game, you must replace the default `controller.yaml` file in the `Company/` folder with your exported `controller.yaml`.
